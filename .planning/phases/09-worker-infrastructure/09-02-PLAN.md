Tests:
1. `start_link/1 starts supervision tree` — start WorkerSupervisor with a unique
   name (to allow parallel test runs), verify `{:ok, sup_pid}` returned and
   `Process.alive?(sup_pid)` is true. Stop in on_exit.

   assert one is `Livekit.Agents.JobSupervisor`, one is `Livekit.Agents.Worker`.
3. `Worker child restarts if killed` — get Worker pid from children, kill it with

   child is alive (different pid, same name if registered).
4. `JobSupervisor child restarts if killed` — same pattern for JobSupervisor.

**job_supervisor_test.exs:**
Module: `Livekit.Agents.JobSupervisorTest`
`use ExUnit.Case, async: true` (no shared global name — use unique name per test)

Setup: start a JobSupervisor with a per-test unique name:
```elixir
setup do
  name = :"job_sup_#{:erlang.unique_integer([:positive])}"
  {:ok, pid} = Livekit.Agents.JobSupervisor.start_link(name: name)
  on_exit(fn -> if Process.alive?(pid), do: GenServer.stop(pid) end)
  %{sup: pid}
end
```

Tests (use `%{sup: sup}` context):
1. `active_jobs/1 returns 0 initially` — assert `JobSupervisor.active_jobs(sup) == 0`
2. `start_job/2 starts a child` — build minimal `AgentSession.Config` (mock session,
   `voice_agent_config: nil`, `server_url: nil`), call `JobSupervisor.start_job(sup, config)`,
   assert `{:ok, pid}` returned, `Process.alive?(pid)` is true,
   `JobSupervisor.active_jobs(sup) == 1`.
3. `active_jobs/1 decrements when child exits` — start a job, then stop the returned
   pid via `GenServer.stop(session_pid)`, `Process.sleep(50)`,
   assert `JobSupervisor.active_jobs(sup) == 0`.
4. `start_job/2 can start multiple children` — start 3 jobs (3 separate configs with
   distinct room names), assert `active_jobs == 3`.

Note: AgentSession.start_link may invoke VoiceAgent and RoomServiceClient internally.
If those fail in tests, add a `try/rescue` and skip the test with
`ExUnit.skip("AgentSession start not yet isolatable")` as a fallback.

Module: `Livekit.Agents.WorkerTest`
`use ExUnit.Case, async: true` (each test uses unnamed worker pid)

Helper:

```elixir
defp start_worker(overrides \\ []) do
  config = struct(Livekit.Agents.Worker.Config, Keyword.merge([
    api_key: "test-key",
    api_secret: "test-secret",
    entrypoint: fn _ctx -> :ok end,
    server_url: nil,      # mock mode — no Gun
    max_concurrent_jobs: 3,
    heartbeat_interval: 60_000,  # don't fire automatically in tests

  ], overrides))

  on_exit(fn -> if Process.alive?(pid), do: GenServer.stop(pid) end)
  pid
end
```

Tests (group by behaviour):

**Registration (mock mode):**
1. `starts and registers in mock mode` — start worker, `Process.sleep(50)`,
   call `Worker.get_status(pid)`, assert `status.registered == true`.
2. `generates worker_id when nil` — start with `worker_id: nil`, assert
   `status.worker_id =~ ~r/^elixir-worker-/`.
3. `preserves supplied worker_id` — start with `worker_id: "my-worker"`, assert
   `status.worker_id == "my-worker"`.

**Heartbeat:**
4. `heartbeat updates last_heartbeat` — start worker, wait for registration
   (`Process.sleep(50)`), capture `status1 = Worker.get_status(pid)`,
   send `send(pid, :heartbeat)`, `Process.sleep(20)`,
   capture `status2 = Worker.get_status(pid)`,
   assert `status2.last_heartbeat != status1.last_heartbeat` OR
   assert `status2.last_heartbeat != nil`.
5. `load reflects active job ratio` — start with `max_concurrent_jobs: 4`,
   assert `get_status(pid).load == 0.0` initially.

**Capacity enforcement:**
6. `rejects availability when at capacity` — The worker must expose an internal
   test helper OR the test sends a mock `{:ws_message, %{"type" => "availability_request", "job_id" => "j1"}}` message. Before that, manually inject fake jobs into state by sending a test message OR just verify via get_status that `active_jobs` count is used.
   Simpler approach: start with `max_concurrent_jobs: 1`. Send the worker a
   `:simulate_job` test message (if the executor added a test backdoor) OR use
   `:sys.replace_state/2` to inject a fake active_jobs map:
   ```elixir
   :sys.replace_state(pid, fn state ->
     %{state | active_jobs: %{"fake-job" => %{session_pid: self(), room_name: "r"}}}
   end)
   ```
   Then assert `get_status(pid).active_jobs == 1`.

**Drain:**
7. `drain returns :ok immediately with no active jobs` — start worker, wait 50ms,
   assert `:ok = Worker.drain(pid)`.
8. `drain waits for in-flight job then returns :ok` — inject one fake active job via
   `:sys.replace_state/2` (session_pid = a live test process). Call `Worker.drain(pid)`
   in a Task (it will block). After 100ms, send the monitored session pid an exit
   signal or stop it. Assert the Task resolves with `:ok` within 2000ms.
   Pattern:
   ```elixir
   session = spawn(fn -> Process.sleep(500) end)
   ref = Process.monitor(session)
   :sys.replace_state(pid, fn state ->
     jobs = %{"job-1" => %{session_pid: session, monitor_ref: ref, room_name: "r", started_at: DateTime.utc_now()}}
     %{state | active_jobs: jobs, draining: false}
   end)
   task = Task.async(fn -> Worker.drain(pid) end)
   Process.exit(session, :normal)
   assert Task.await(task, 2_000) == :ok
   ```
9. `drain times out when jobs take too long` — set `drain_timeout: 200`, inject a
   long-running session (sleep 10_000ms), call `Worker.drain(pid)` with timeout
   500ms, assert `{:error, :timeout}` (or the call raises after 200ms drain_timeout).

**get_status fields:**
10. `get_status returns required fields` — assert status map has keys:
    `[:worker_id, :registered, :active_jobs, :max_concurrent_jobs, :last_heartbeat,
      :draining, :load, :uptime_seconds]`.
