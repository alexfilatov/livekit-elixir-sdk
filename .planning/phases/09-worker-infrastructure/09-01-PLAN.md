Note: The LiveKit agent WebSocket protocol uses binary protobuf frames. The server
sends WorkerMessage envelopes; the worker sends WorkerMessage envelopes back. The
minimal messages needed are:
- Register (worker -> server): worker_id, name, version, available_jobs, load
- RegisterResponse (server -> worker): worker_id, server_version
- AvailabilityRequest (server -> worker): job details
- AvailabilityResponse (worker -> server): job_id, available bool
- JobAssignment (server -> worker): job struct with job_id, room, participant
- KeepAlive / Pong (worker -> server): heartbeat response

Because the full livekit_models.pb.ex may not exist yet, the executor should define
a minimal internal protocol representation using plain Elixir maps and encode/decode
stubs that can be filled in once the real protobufs are available. For now, encode
messages as Jason JSON over the WebSocket text frame (not binary), so mock tests can
inspect the payloads without a full protobuf dependency.

with a real Gun WebSocket + OTP-correct GenServer. Preserve the Config and public API
surface so existing callers are unaffected.

**Config struct changes (additive only):**
Keep all existing fields. Rename `health_check_interval` to `heartbeat_interval`
(default 30_000 ms). Remove `reconnect_attempts` field (use exponential backoff
internally). Add:
- `namespace :: String.t()` — agent namespace (default `"default"`)
- `drain_timeout :: pos_integer()` — ms to wait for jobs during drain (default 60_000)

**State struct changes:**
Keep all existing fields. Replace `connection :: pid() | nil` with:
- `gun_pid :: pid() | nil` — the Gun connection process
- `gun_monitor :: reference() | nil` — monitor ref for the Gun process
- `ws_stream :: reference() | nil` — Gun stream reference for upgraded WS
- `draining :: boolean()` — true when drain/1 has been called
- `drain_from :: GenServer.from() | nil` — caller to reply to when drain completes

**Public API (preserve existing + add):**
- Keep: `start_link/2`, `get_status/1`, `list_active_jobs/1`
- Remove (were mock-only): `register_worker/1`, `unregister_worker/1`, `update_config/1`, `terminate_job/1`
- Add: `drain/1` — `GenServer.call(pid, :drain, 90_000)`

**init/1:**
- Validate config (require api_key, api_secret, entrypoint — same as before)
- Generate worker_id if nil
- Schedule `:connect` via `send(self(), :connect)` immediately
- Do NOT start heartbeat yet (start after successful WebSocket upgrade)

**Connection flow (mock mode when server_url is nil OR starts with "mock://"):**
- `handle_info(:connect, state)`: if mock mode, set `registered: true`,
  `gun_pid: nil`, schedule first heartbeat, log "mock mode". Otherwise call
  `connect_to_server/1` to open Gun connection.
- `connect_to_server/1`:
  1. Parse URI from `config.server_url` (ws:// or wss://)
  2. `{:ok, gun_pid} = :gun.open(host_charlist, port, %{protocols: [:http]})`
  3. Monitor gun_pid
  4. Return `{:ok, %{state | gun_pid: gun_pid}}`
- `handle_info({:gun_up, gun_pid, :http}, state)`: upgrade to WebSocket:
  ```
  stream = :gun.ws_upgrade(gun_pid, "/agent", [
    {"x-livekit-worker-id", state.config.worker_id}
  ])
  {:noreply, %{state | ws_stream: stream}}
  ```
- `handle_info({:gun_upgrade, _gun_pid, _stream, ["websocket"], _headers}, state)`:
  send register message, schedule heartbeat, set `registered: true`.
  Register message (JSON encoded text frame):
  ```json
  {"type":"register","worker_id":"<id>","max_concurrent_jobs":<n>,"load":0.0,"namespace":"<ns>"}
  ```
  Send via `:gun.ws_send(state.gun_pid, state.ws_stream, {:text, Jason.encode!(msg)})`
- `handle_info({:gun_ws, _gun_pid, _stream, {:text, data}}, state)`:
  decode JSON, dispatch on `"type"` field:
  - `"register_response"` → log success
  - `"availability_request"` → call `handle_availability_request/2`
  - `"job_assignment"` → call `handle_job_assignment/2`
  - unknown → Logger.debug
- `handle_info({:gun_down, _pid, _proto, reason, _}, state)`:
  clear connection state, schedule reconnect with exponential backoff (1s, 2s, 4s... up to 30s)
  via `Process.send_after(self(), :connect, backoff_ms)`. Track backoff in state.
- `handle_info({:DOWN, ref, :process, _pid, reason}, state)` when `ref == state.gun_monitor`:
  same as gun_down — reconnect logic.

**Heartbeat:**
- `handle_info(:heartbeat, state)`:
  - Compute `load = map_size(state.active_jobs) / state.config.max_concurrent_jobs`
  - In real mode: `:gun.ws_send(state.gun_pid, state.ws_stream, {:text, Jason.encode!(%{type: "keepalive", load: load})})`
  - In mock mode: Logger.debug
  - Update `last_heartbeat: DateTime.utc_now()`
  - Schedule next heartbeat: `Process.send_after(self(), :heartbeat, state.config.heartbeat_interval)`
  - Do NOT reschedule if draining AND no active jobs

**Availability and job assignment:**
- `handle_availability_request/2`: if `draining` or at capacity, send
  `{"type":"availability_response","job_id":"<id>","available":false}`.
  Otherwise send `available: true`.
- `handle_job_assignment/2`: extract job_id, room_name, participant_identity from
  the JSON payload. Build `AgentSession.Config`, call `JobSupervisor.start_job/2`.
  On success: monitor the returned session pid, add to `active_jobs` map as
  `%{session_pid: pid, monitor_ref: ref, room_name: room, started_at: DateTime.utc_now()}`.
  On failure: log error, increment jobs_failed metric.
- `handle_info({:DOWN, ref, :process, pid, reason}, state)` for job sessions
  (ref NOT equal to gun_monitor): remove the job from active_jobs, update metrics.
  If draining and `active_jobs` is now empty, reply `:ok` to the drain caller
  and stop: `GenServer.stop(self(), :normal)`.

**Drain:**
- `handle_call(:drain, from, state)`:
  - Set `draining: true`, `drain_from: from`
  - Send `{"type":"deregister"}` to server if connected
  - If `active_jobs` is empty, reply `:ok` immediately and stop
  - Otherwise return `{:noreply, new_state}` — the reply is deferred until all
    jobs finish (see DOWN handler above)
  - Enforce drain_timeout: `Process.send_after(self(), :drain_timeout, state.config.drain_timeout)`
- `handle_info(:drain_timeout, state)`:
  - If still draining, log warning, reply drain_from with `{:error, :timeout}`, stop

**get_status/1:**
Add `draining`, `load` (active/max ratio), `namespace` to the returned map.

**terminate/2:**
Close gun connection if open: `:gun.close(state.gun_pid)`.

- `@impl true` on all callbacks
- State updates via struct update syntax

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker → LiveKit server | WebSocket carries job assignments and credentials; attacker controlling the server can send arbitrary job payloads |
| job assignment payload → AgentSession | JSON decoded from server controls room_name and participant_identity |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Spoofing | Worker WebSocket handshake | mitigate | Worker sends api_key + HMAC-signed worker_id header; validate RegisterResponse before accepting jobs |
| T-09-02 | Tampering | Job assignment payload | mitigate | Validate room_name is non-empty string, participant_identity is non-empty string; reject malformed JSON with Logger.warning |
| T-09-03 | Denial of Service | Unbounded job spawning | mitigate | max_concurrent_jobs cap enforced in handle_availability_request before accepting job |
| T-09-04 | Information Disclosure | api_secret in logs | mitigate | Use sanitize_for_logging pattern (already in JobContext); never log api_secret in Worker |
| T-09-05 | Elevation of Privilege | Arbitrary entrypoint via job metadata | accept | entrypoint is a compile-time function reference, not runtime-configurable from server payloads |
</threat_model>
