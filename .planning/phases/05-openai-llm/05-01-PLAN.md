<objective>
Refactor `lib/livekit/agents/llm/openai.ex` from a GenServer mock into a pure
functional module implementing `@behaviour Livekit.Agents.LLM`. The module must:

- Send real HTTP POSTs to `/v1/chat/completions` via Tesla (already in deps)
- Convert `ChatContext` items to the OpenAI messages wire format
- Parse response into a `FunctionCall` struct (tool call) or `ChatMessage` (text)
- Stream SSE lines from `/v1/chat/completions` with `stream: true`, emitting `LLMChunk` messages to the caller
- Truncate `ChatContext` by token estimate before sending (4 chars ≈ 1 token)
- Fall back to mock mode when `config.mock: true` or `api_key` is absent

Purpose: Provide the real LLM provider that the voice pipeline (Phase 7) and Tool
execution loop (`Tool.run/3`) will call.

Output: Single file `lib/livekit/agents/llm/openai.ex` (replaces the GenServer mock).

**Config struct additions** (keep all existing fields):
- `mock: false` — return synthetic responses without API calls
- `base_url: "https://api.openai.com"` — overridable for Bypass tests

**validate_config/1:**
- If `config.mock == true` → `:ok`
- If `config.api_key` is nil or `""` → `{:error, :missing_api_key}`
- Otherwise → `:ok`

**chat/2 signature:** `def chat(%ChatContext{} = ctx, opts \\ [])`
- Extract options: `model` (default from config.model), `temperature`, `max_tokens`,
  `tool_context` (optional `ToolContext.t()`), `config` (required `Config.t()`)
- If mock mode → return `{:ok, mock_chat_response()}`
- Otherwise:
  1. Truncate ctx to `config.max_tokens * 4` chars worth of items via `ChatContext.truncate/2`
     (estimate: `div(config.max_tokens, 1) |> max(20)` items as a safe upper bound; keep simple)
  2. Convert ctx.items to OpenAI messages via `to_openai_messages/1`
  3. Build request body: `%{model: model, messages: messages, temperature: temperature, max_tokens: max_tokens}`
  4. If `tool_context` opt present: add `tools: ToolContext.to_openai_tools(tool_context)` to body
  5. POST to `/v1/chat/completions` using `build_client(config)`
  6. Parse response: if `tool_calls` present in first choice → return `FunctionCall` struct;
     otherwise return `ChatMessage` struct

**stream/2 signature:** `def stream(%ChatContext{} = ctx, opts \\ [])`
- Capture `subscriber = self()` before spawning
- If mock mode → spawn process that sends one `:text` chunk then `:done`, return `{:ok, pid}`
- Otherwise: spawn process that:
  1. Builds body same as chat/2 but adds `stream: true`
  2. Uses `Tesla.Adapter.Hackney` with `recv_timeout: 60_000`
  3. POSTs to `/v1/chat/completions`
  4. Iterates SSE response body: split on `\n`, filter lines starting with `"data: "`,
     strip prefix, skip `"[DONE]"`, decode JSON, extract `delta.content` or `delta.tool_calls`,
     send `{:llm_chunk, %LLMChunk{type: :text, content: text}}` for text deltas
  5. Sends `{:llm_chunk, %LLMChunk{type: :done}}` when stream ends
  6. On error: sends `{:error, reason}` to subscriber

**to_openai_messages/1** (private, converts ChatContext items to OpenAI wire format):
- `%ChatMessage{role: :system, content: parts}` → `%{"role" => "system", "content" => content_to_string(parts)}`
- `%ChatMessage{role: :user, content: parts}` → `%{"role" => "user", "content" => content_to_string(parts)}`
- `%ChatMessage{role: :assistant, content: parts}` → `%{"role" => "assistant", "content" => content_to_string(parts)}`
- `%ChatMessage{role: :tool, content: parts}` → `%{"role" => "tool", "content" => content_to_string(parts)}`
  (tool messages need tool_call_id — omit for now; will be enhanced when pipeline integrates)
- `%FunctionCall{call_id: id, name: name, arguments: args}` →
  `%{"role" => "assistant", "tool_calls" => [%{"id" => id, "type" => "function", "function" => %{"name" => name, "arguments" => args}}]}`
- `%FunctionCallOutput{call_id: id, name: name, output: out}` →
  `%{"role" => "tool", "tool_call_id" => id, "name" => name, "content" => out}`

**content_to_string/1** (private):
- Single string in list → return string
- Multiple items / maps → Jason.encode!/1

**parse_chat_response/2** (private, takes `%Tesla.Env{}` and `ctx`):
- On `%{status: 200, body: body}`:
  - `choice = List.first(body["choices"])`
  - `message = choice["message"]`
  - If `message["tool_calls"]` is non-empty list:
    - Map each to `ChatContext.new_function_call(tc["id"], tc["function"]["name"], tc["function"]["arguments"])`
    - Return `{:ok, List.first(function_calls)}` (return first; Tool.run loop handles multiple via re-invocation)
  - Else:
    - content = message["content"] || ""
    - Return `{:ok, ChatContext.new_message(:assistant, [content])}`
- On other status: `{:error, {:api_error, status, body}}`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → chat/2 | ChatContext items and opts arrive from application code; content not sanitized |
| Tesla → OpenAI API | API key in Authorization header; response body is untrusted JSON |
| stream process → subscriber | SSE chunks forwarded as-is from OpenAI; tool_call arguments are opaque JSON strings |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Information Disclosure | build_client/1 | mitigate | API key is in Bearer header only; never logged. Tesla.Middleware.Logger is NOT included in build_client/1 (unlike the mock's create_http_client which had it). |
| T-05-02 | Spoofing | parse_chat_response/2 | accept | Response comes from OpenAI over TLS; Hackney validates server cert by default. Low residual risk. |
| T-05-03 | Denial of Service | stream/2 SSE loop | mitigate | Hackney recv_timeout: 60_000 caps hanging streams. Spawned process exits naturally or on timeout. |
| T-05-04 | Tampering | tool_call arguments | accept | Arguments are opaque JSON strings forwarded to Tool.run; Tool.run decodes and passes to handler. Validation is the handler's responsibility. |
</threat_model>
