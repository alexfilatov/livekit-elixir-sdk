**handle_cast({:push_frame, frame}, state):**
1. Classify frame: classification = EnergyVAD.classify(frame, state.vad_config)
2. TurnDetector.push_frame(state.turn_detector, {classification, frame})
3. If classification == :speech AND state.active_task != nil (TTS in progress):
   - Task.shutdown(state.active_task, :brutal_kill)
   - Set active_task: nil, status: :idle
   - TurnDetector.reset(state.turn_detector) — discard pending turn_end for old turn
4. Update metrics.audio_frames_processed + 1, metrics.last_activity
5. {:noreply, state}

**handle_info({:turn_end, frames}, state) — this is the main processing pipeline:**

This message arrives from TurnDetector when a speaking turn completes.
Run STT -> LLM -> TTS asynchronously so the GenServer is never blocked:

```elixir
task = Task.async(fn ->
  with {:ok, speech_event} <- do_stt(frames, config, stt_opts),
       :ok <- emit_telemetry(:stt_complete, %{text: speech_event.text}, state),
       chat_ctx <- ChatContext.add(state.chat_context,
                     ChatContext.new_message(:user, [speech_event.text])),
       {:ok, llm_response} <- do_llm(chat_ctx, config, llm_opts),
       :ok <- emit_telemetry(:llm_first_token, %{role: llm_response.role}, state),
       {:ok, audio_binary} <- do_tts(llm_response.content, config, tts_opts),
       :ok <- emit_telemetry(:tts_start, %{bytes: byte_size(audio_binary)}, state) do
    {:ok, speech_event.text, llm_response, audio_binary}
  end
end)
```

Set state.active_task = task, state.status = :processing.
{:noreply, state}

**handle_info({:turn_start, _timestamp_us}, state):**
- Update metrics.last_activity; {:noreply, state}

**handle_info({ref, result}, state) when is_reference(ref) — Task completion:**
- Match when state.active_task != nil and state.active_task.ref == ref
- Process.demonitor(ref, [:flush])
- Handle {:ok, user_text, llm_response, audio_binary}:
  1. Add assistant message to chat_context: ChatContext.add(ctx, ChatContext.new_message(:assistant, [llm_response.content]))
  2. Update metrics.turns_processed + 1
  3. Log the completed turn
  4. Set status: :idle, active_task: nil
- Handle {:error, reason}: log error, metrics.errors + 1, set status: :idle, active_task: nil
- {:noreply, updated_state}

**handle_info({:DOWN, ref, :process, _pid, reason}, state) when task exits abnormally:**
- Log warning, update errors metric, reset active_task: nil, status: :idle
- {:noreply, state}

**handle_call(:get_metrics, _from, state):**
- {:reply, state.metrics, state}

**Private helpers:**

```elixir
defp do_stt(frames, config, opts) do
  {stt_module, _stt_config} = config.stt
  audio_binary = frames |> Enum.map(& &1.data) |> IO.iodata_to_binary()
  stt_module.transcribe(audio_binary, opts)
end

defp do_llm(chat_context, config, opts) do
  {llm_module, _llm_config} = config.llm
  llm_module.chat(chat_context, opts)
end

defp do_tts(text, config, opts) do
  {tts_module, _tts_config} = config.tts
  tts_module.synthesize(text, opts)
end

defp emit_telemetry(event, measurements, _state) do
  event_name = [:livekit, :agents, :pipeline, event]
  metadata = %{monotonic_time: System.monotonic_time()}
  :telemetry.execute(event_name, measurements, metadata)
  :ok
end
```

Note: providers are called as `stt_module.transcribe(...)` passing the audio binary
directly. The {module, config} config tuple carries provider-specific config; for v1
the config is not passed per-call (providers are stateless via their own init). If a
provider needs its config at call time it can be passed via opts. This keeps the
pipeline provider-agnostic (PIPE-05 — any conforming module works).

Telemetry event names (PIPE-06):
- [:livekit, :agents, :pipeline, :stt_complete]
- [:livekit, :agents, :pipeline, :llm_first_token]
- [:livekit, :agents, :pipeline, :tts_start]

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| audio producer → push_frame/2 | Audio frames from external LiveKit room participants |
| Pipeline → STT/LLM/TTS providers | Network calls to external AI APIs |
| STT transcript → LLM chat context | Transcript text from external audio becomes LLM input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-02-01 | Denial of Service | push_frame/2 cast mailbox | accept | async cast design; audio arrives at bounded real-time rate; process mailbox is the natural buffer |
| T-07-02-02 | Tampering | STT transcript → LLM input | accept | transcript is user speech; the LLM system prompt is developer-controlled and not modified by transcript content |
| T-07-02-03 | Denial of Service | Task.async STT/LLM/TTS | mitigate | active_task tracking ensures only one Task runs at a time; Task.shutdown(:brutal_kill) on interruption prevents leaked tasks |
| T-07-02-04 | Information Disclosure | :telemetry measurements | accept | telemetry is in-process (no network); measurements contain only byte counts and timing — no transcript content |
| T-07-02-05 | Denial of Service | LLM chat_context growth | accept | ChatContext.truncate/2 available; pipeline v1 does not auto-truncate; operator responsibility to configure appropriately |
</threat_model>
