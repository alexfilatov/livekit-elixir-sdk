<objective>
Implement `Livekit.Agents.RoomIO` — a GenServer that bridges a WebRTC Room to the
voice Pipeline — and refactor `AgentSession` to use real Room + RoomIO + Pipeline
when a server URL is provided.

Purpose: Audio must flow Room → RoomIO → Pipeline → RoomIO → Room. This phase wires
those three components together so an agent session connected to a real LiveKit server
can process participant speech through the full STT → LLM → TTS pipeline and publish
synthesised audio back to the room.

Output:
- `lib/livekit/agents/room_io.ex` — new GenServer (RoomIO)
- `lib/livekit/agents/agent_session.ex` — rewritten to use real Room/RoomIO/Pipeline
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Room NIF → RoomIO | Unvalidated binary audio data crosses from Rust into Elixir |
| Pipeline → RoomIO | {:pipeline_audio, frame} sent by Pipeline task — frame data is synthesised audio |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | D (DoS) | RoomIO handle_info :audio_frame | mitigate | Pipeline.push_frame/2 is a non-blocking cast; RoomIO mailbox bounded by room audio rate — no accumulation risk beyond normal audio bandwidth |
| T-12-02 | T (Tampering) | RoomIO audio_frame binary | accept | Binary originates from Rust NIF trust boundary (Phase 11); AudioFrame wraps without parsing — no injection vector |
| T-12-03 | D (DoS) | AgentSession mock simulate_room_events | accept | spawn_link loop only active when server_url is nil (dev/test mode); no production impact |
| T-12-04 | E (Elevation) | AccessToken generation in AgentSession | mitigate | api_key/api_secret kept in Config struct only (not logged); Logger.info calls must not include token value — use config.room_name in log messages only |
</threat_model>
