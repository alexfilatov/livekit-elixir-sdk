**Module 1: `Livekit.Agents.LLM`** (the behaviour)

Per D-03 and D-09:

Structure (follow CONVENTIONS.md module order):
1. `@moduledoc` — explain the LLM contract. Note that `chat_context` is typed as `term()` in Phase 1 and will be tightened to `Livekit.Agents.ChatContext.t()` in Phase 2. Show a batch usage example and a streaming usage example.

   - `@type config :: map()` (per D-16)
   - `@type chat_context :: term()` — add comment: `# Will be tightened to ChatContext.t() in Phase 2`
   - `@type chat_message :: %{role: atom(), content: String.t()}`
   - `@type error_reason :: :api_error | :timeout | :invalid_config | :rate_limited | term()` (per D-13)
4. Callback declarations (per D-03):
   - `@callback chat(chat_context :: chat_context(), opts :: keyword()) :: {:ok, chat_message()} | {:error, error_reason()}`
   - `@callback stream(chat_context :: chat_context(), opts :: keyword()) :: {:ok, pid()} | {:error, error_reason()}` — document that the returned pid sends `{:llm_chunk, %LLMChunk{}}` to `self()` at call time; a chunk with `type: :done` signals end of stream
   - `@callback capabilities() :: %{streaming: boolean(), tool_calling: boolean(), vision: boolean(), max_context_tokens: pos_integer() | nil}` (per D-09)
   - `@callback validate_config(config :: config()) :: :ok | {:error, error_reason()}` (per D-15)
5. `@optional_callbacks [stream: 2, validate_config: 1]` — NOTE: LLM stream is arity 2 (chat_context + opts), so this MUST be `stream: 2` not `stream: 1` (per pitfall 4; arity must exactly match the callback signature)

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `validate_config/1` default in LLM | accept | Default returns `:ok` — same rationale as T-01-01. LLM providers handling API keys must override `validate_config/1` to verify the key is present. This expectation is documented in the behaviour's `@moduledoc`. |
| T-02-02 | Information Disclosure | `LLMChunk.content :: term()` | accept | `term()` is intentionally open — content for `:tool_call` type will be structured in Phase 3. No PII flows through the behaviour definition itself. |
| T-02-03 | Denial of Service | VAD streaming process never exits | accept | The behaviour contract documents that VAD streaming processes exit on error by sending `{:error, reason}`. Lifecycle enforcement is the provider's responsibility. Documented in `stream/1` callback `@doc`. |

No ASVS categories apply to pure behaviour module definitions.
</threat_model>
