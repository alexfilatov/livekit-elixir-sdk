Any conforming provider module can be swapped in without Pipeline code changes.

**Module 1: `Livekit.Agents.STT`** (the behaviour)

1. `@moduledoc` — explain the contract, show batch usage and streaming usage examples
2. `alias Livekit.Agents.STT.SpeechEvent` — forward alias so @callback specs can use SpeechEvent.t()

   - `@type config :: map()` (per D-16)
   - `@type error_reason :: :api_error | :timeout | :invalid_config | :rate_limited | term()` (per D-13)

   - `@callback transcribe(audio :: binary(), opts :: keyword()) :: {:ok, SpeechEvent.t()} | {:error, error_reason()}`
   - `@callback stream(config :: config()) :: {:ok, pid()} | {:error, error_reason()}` — document that the returned pid sends `{:speech_event, %SpeechEvent{}}` to `self()` at call time; the terminal event has `type: :end`

@moduledoc example showing a conforming provider (show `use Livekit.Agents.STT`, `@impl true`, `def transcribe`, `def capabilities`).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| None | This plan creates pure Elixir behaviour module definitions. No external I/O, no network calls, no user input, no secrets. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | `validate_config/1` default | accept | Default returns `:ok` — safe because it is a contract default that providers MUST override when real validation is needed. The behaviour contract documents this expectation. |
| T-01-02 | Information Disclosure | `@type error_reason` includes `term()` | accept | `term()` allows providers to surface arbitrary error details. Acceptable: callers must pattern-match known atoms; unknown terms are treated as opaque errors. No PII flows through behaviour definitions. |

No ASVS categories apply to pure behaviour module definitions. Security threats manifest at provider implementation time (Phase 4, 5, 6), not at contract-definition time.
</threat_model>
